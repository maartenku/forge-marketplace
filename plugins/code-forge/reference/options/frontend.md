# Frontend

Default: Angular 21 LTS with standalone components and signals, NgRx Signal Store per feature (the classic Store only where a project already uses it), Spartan NG (`@spartan-ng/brain` headless primitives plus the copy-in `helm` UI) with Tailwind, and pnpm, ESLint, Prettier, Vitest and Playwright as tooling. The layout is `src/Web/src/app/{core,shared,features/[slug]}`. The only runtime packages are `@angular/*`, `@ngrx/signals`, `@spartan-ng/brain`, `@angular/cdk` and `tailwindcss`. The client for our own API is generated by NSwag from the backend's OpenAPI document into `core/api/api.generated.ts` and committed, so there are no hand-written HTTP calls to our own API. Details are in the base profiles.

Spartan NG was chosen because its components are copied into the project rather than imported from a library, so a design system can restyle them without fighting upstream.

| Alternative | Composition | Pick when | Watch out |
|---|---|---|---|
| No frontend | base `api-dotnet` | the project is an API, a worker, a scheduled job or a CLI | if a UI appears later, add the Angular workspace next to the API; the layout is designed for that |
| React | Vite, React 19, TypeScript, TanStack Router and Query, Zustand, shadcn/ui with Tailwind | a tiny project, a React-only library, or staying fluent in React | keep the same feature-folder layout and design tokens so designs transfer |
| Plain HTML | HTML, Tailwind, Alpine or htmx or vanilla TypeScript | static sites, demos | once routing or state appears, move to Angular |
| Angular with Material | the default with Material instead of Spartan | a standard admin-tool look is enough | theming Material to a custom design costs more than restyling Spartan |

Design-system hook, planned: a token file (colours, type scale, spacing, radius, variants) that Claude Design gets as its style reference and that `src/Web` imports as Tailwind configuration. Until it exists, projects ship Spartan defaults with a small token override.
